# 출입 규칙·관측 품질 코드 수정

## 반영한 내용

- 조사 기록상 매일 운영하는 안양역1·2노상(ID 53/48)의 일요일 10:00~22:00 출입시간을 보완 스크립트에 명시한다.
- 요일별 `*_access_status`는 `open`/`closed`/`unknown`이다. 명시적인 closed가 아니면 빈 시간 또는 00:00~00:00을 휴무로 단정하지 않는다.
- 출입시간 보완 전에 CSV의 모든 ID/이름을 로컬 DB의 lots와 대조한다. 불일치·중복은 저장 전에 오류로 처리하며, 원본 CSV를 .csv.bak으로 보관한다.
- A18은 전체 DB의 공통 기간으로 모든 예측 대상의 결측률을 계산한다. 관측이 전혀 없는 대상과 park_count 결측도 포함한다.
- A18/A19는 관측 시각 이후의 5분 격자에서 이용 가능한 최신 유효 관측을 쓴다. 미래 보간이나 결측 채움은 하지 않는다.
- 120분 초과 요청은 unsupported_horizon으로 예측 수치를 숨긴다. 지원 범위 안에서 사용한 모델 시점은 model_horizon_min으로 반환한다.
- 원천 폴링이 실패해도 같은 프로세스의 다음 시도까지 5분 간격을 유지한다.

## 데이터 적용 순서

코드 변경만으로 기존 CSV나 모델 파일이 갱신되지는 않는다. 아래 명령은 기존 A18/A19용 가로형 CSV인 data/processed/parking_access_rules.csv에 적용한다.
새 서비스 검증기에서 쓰는 data/raw/parking_access_rules.csv는 요일별 한 행의 별도 스키마이며, 두 파일을 서로 덮어쓰지 않는다.
프로젝트 루트에서 실행한다.

```bash
python scripts/fill_access_schedule.py
python src/analysis/a18_continuity_check.py
python src/analysis/a19_persistence_baseline.py
```

첫 명령이 ID/이름 불일치로 중단되면 CSV를 실제 DB와 대조한 뒤 다시 실행한다.
조사 메모에는 삼덕공원지하 ID 2, 박달시장2노외 ID 53이라는 기록이 있으나,
DB 기반 조사표에는 각각 38, 33으로 적혀 있다. 이후 사용자 로컬 실행에서 CSV 전체 ID/이름 검사가 통과했다.
따라서 이 실행에 사용한 CSV의 ID 불일치를 미해결 문제로 남기지 않는다.

## 검증 범위와 남은 작업

GitHub Actions는 Python 3.12에서 합성 데이터 회귀 테스트, 기존 폴링 테스트와 새 서비스 출입 규칙 검증기 테스트를 실행한다.
사용자 로컬에서 출입시간 보완과 A18/A19 실행이 완료됐다. 68곳·286,960행의 관측으로 산출한
출입 가능 시간의 Persistence MAE는 15/30/60/120분 각각 2.565/4.103/6.650/11.029%p다.
사용자 제공 출력의 구간별 표본 수와 총합도 일치한다. 최신 DB를 검토 환경에서 직접 재실행한 것은 아니다.
실행 근거·전체 표·해석 한계는 [A18/A19 실행 결과](tables/a19_persistence_summary.md)에 기록했다.

- 초기 첨부 CSV/마크다운/HTML은 열람하지 못했다. 이후 첨부된 A18 실행 로그와 대화로 제공된 A19 완료 출력은 확인했다.
- CSV/DB의 ID 일치와 별개로, 실제 출입시간의 현장 근거 및 시간대별 데이터 경직은 추가 검증 대상이다.
- 기존 U11/서빙의 이상값 제한(최대 120%)은 A18/A19의 정원 초과 제외와 다르다.
  A19의 전체 기간 수치를 U11 또는 A20의 테스트 구간 점수와 직접 비교하지 않는다.
  다음 모델 실험은 같은 관측 전처리, 과거/보정/test 분할, 평가 행으로 기준선을 다시 산출해야 한다.
- 공휴일별 출입 예외, 입차/출차 구분, 폐쇄시간을 가로지르는 주차 가능 여부는 아직 추천 파이프라인에 연결되지 않았다.
- 다일 주차의 일별 요금 상한, 공휴일 요금 처리, UI의 실제 API 연결과 잔여 면수 변환은 이번 수정에 포함되지 않았다.
- 1~120분 중 학습 격자(15/30/60/120)와 다른 요청은 가까운 모델 시점의 근사이며, model_horizon_min을 확인해야 한다.
