# 예측 성능 개선 실행계획

기준일: 2026-09-17  
정본 역할: 성능 실험의 목표·순서·합격 기준. 과거 U/A 보고서는 실험 기록이며, 현재 판단은 이 문서와 `reports/performance_status.md`를 따른다.

## 1. 재정립한 목표

서비스 목표는 **목적지와 주차시간을 입력받아, 실제 출입 가능한 주차장 중 도착 시 혼잡 위험과 정확한 예상요금을 함께 비교해 추천하는 것**이다.

예측 목표는 더 이상 15~120분으로 고정하지 않는다. 데이터로 검증해 다음을 찾는다.

> **점유율 MAE 10%p 이하이면서 강한 기준선보다 우수한 최대 예측 지평선**

다만 추천의 핵심은 도착 시점이다. 검증 범위를 넘는 먼 미래는 `AI 예측`으로 표시하지 않고 `과거 패턴 기반 예상` 또는 `예측 불가`로 구분한다.

## 2. 확정된 모델 전략

- 주력: **전 주차장을 함께 학습하는 글로벌 LightGBM**
- 출력: 주차장 ID, 해당 주차장의 현재값·lag·운영정보를 사용한 **주차장별 예측**
- 이유: 보유 기간이 17일이라 개별 주차장 모델은 요일별 반복이 2~3회뿐이다.
- 다음 후보: 글로벌 모델 뒤에 주차장별 편향/잔차 보정
- 개별 모델: 반복적으로 실패한 주차장에 한해 동일 평가행에서 우수성이 재현될 때만 채택
- Prophet: 6~24시간 구간의 비교군. 검증 없이 앙상블하지 않는다.
- LSTM/GRU/TFT: 현재 주력에서 제외하고 장기 데이터 축적 후 비교한다.

## 3. 공통 평가 원칙

1. 랜덤 분할 금지. 시간순 rolling-origin만 사용한다.
2. AI와 기준선은 완전히 같은 평가행으로 비교한다.
3. 데이터 경직·출입 통제·요금징수시간을 서로 다른 축으로 관리한다.
4. 미래 정답 시각이 `label_valid`가 아닌 행은 학습·평가에서 제외한다.
5. 전체 평균 외에 평일/주말, 주차장별 성능과 제공률을 함께 보고한다.
6. MAPE 대신 점유율 **MAE(%p)** 를 사용한다.
7. 미달·평가불가가 있으면 보고서 상태는 `partial`이다.
8. 통과 수치는 산출물 CSV/JSON에서 자동 집계한다.

## 4. 실험 순서

### P0 — A23 최대 검증 지평선

직접 예측 모델을 지평선별로 비교한다. 재귀적으로 예측을 이어 붙이지 않는다.

- 지평선: 15, 30, 60, 120, 180, 240, 360, 720, 1440분
- 기준선: persistence, `lag_24h`, 가능한 경우 `lag_7d`, 요일×시각 seasonal naive
- 모델 M0: 현재 글로벌 Δ-LightGBM
- 모델 M1: M0 + `lag_24h`/`lag_7d` + time-of-week + 공휴일
- 비교군 M2: 360분 이상 Prophet

지평선 `h`의 인증 조건:

- 전체 MAE ≤ 10%p
- 평일과 주말 각각 MAE ≤ 10%p
- 해당 지평선의 가장 강한 기준선보다 MAE가 낮음
- 평가 가능한 주차장의 80% 이상이 MAE ≤ 10%p
- 최소 2회 주말을 포함한 복수 test 날짜에서 방향이 재현됨

하나라도 미달이면 그 지평선 이후를 자동 통과시키지 않는다. 현재 데이터로는 탐색 결과만 내고, 최종 인증은 추가 날짜로 재검증한다.

### P0 — A24 글로벌/개별/혼합 비교

- G0: 현재 글로벌 모델
- L0: 주차장별 개별 모델
- H0: 글로벌 + 주차장별 validation 잔차 보정

같은 행·같은 분할로 비교한다. H0 또는 L0가 이후 test 날짜에서도 G0보다 좋아질 때만 서비스에 반영한다. test 결과로 라우터를 만들지 않는다.

### P0 — 만차 강등 가치 검증

- A: 강등 없음
- B: `full_prob > cutoff` 강등
- C: 현재 점유율 기준 강등

필수 지표:

1. A와 B의 순위 변경률
2. A의 1위가 도착 시 실제 혼잡(점유율 90% 이상)이었던 비율
3. B가 그 사례에서 실제 여유 주차장으로 1위를 바꾼 비율

`full_prob` 보정이 미달이면 내부 실험값으로만 쓰고 UI에서 확정 확률처럼 표현하지 않는다.

### P1 — 예측 구간 품질

U11은 `partial`이고 노출 게이트는 0/16이다. 점 예측과 강등 실험을 막지는 않지만 `[p10,p90]`은 계속 숨긴다. 추가 데이터 후 커버리지 0.77~0.83과 폭을 함께 재검증한다.

### P1 — GITS 활용

1. `parking.db`와 시각·누락·값을 대조하는 품질검사
2. 타 지자체의 값 의미와 이상치를 지역별 검증
3. 다지역 사전학습 후 안양 fine-tuning 실험
4. 현재/과거 주변 점유율 피처 ablation 재실험

안양 21개 고정 피드는 GITS에서도 고정이므로 복구 수단으로 쓰지 않는다. GITS 요금·유형도 서비스 정본으로 쓰지 않는다.

## 5. 서비스와 병행할 필수 작업

- 조사 결과를 구조화된 출입·과금 CSV로 계속 적재
- 폐쇄시간에 주차시간이 걸치면 추천 제외
- 운영시간 밖 데이터 경직 구간은 예측 차단
- 누진요금·무료시간·일일권·사용자 감면을 비교한 최저 적법 요금 반환
- 실제 API fixture 3개와 UI 연결·스크린샷 확보
- 최신성 감시와 재현 가능한 분석 입력 복구

OAuth, 월정기권 판매, 사용자 제보는 핵심 추천·검증 이후다.

## 6. 완료 정의

- **점 예측 완료:** 인증 지평선과 실패 지평선을 날짜·표본·기준선과 함께 보고
- **추천 효과 완료:** 강등으로 헛걸음을 줄인 비율을 독립 test에서 산출
- **구간 완료:** 노출 게이트 통과. 그전에는 `partial`
- **서비스 완료:** 출입 필터·요금·예측·강등이 실제 API/UI에서 같은 시각 기준으로 동작
