# 안양시 경진대회 사업계획서 — 항목별 작성 프롬프트

작성일: 2026-09-16

목적: `모창 프롬프트 예시.md`에서 이번 대회에 필요한 질문만 골라 공식 양식의 7개 항목에 맞췄다. **이 파일은 사업계획서 본문이 아니라 본문을 작성·검토하는 프롬프트 모음이다.** 대괄호 안은 우리 프로젝트 기준 임시 입력값이며, 팀이 수정한 뒤 사용한다.

## 1. 무엇을 가져오고 무엇을 뺐나

|---|---|
| Q1·Q11 한 줄 소개 | 1번에 통합. 누구의 어떤 문제를 어떻게 해결하는지 먼저 설명 |
| Q2 시작 배경 | 1번. 구체적인 이용 장면 → 불편 → 해결 흐름. 가상의 장면을 실제 경험으로 포장하지 않음 |
| Q3-1 차별화 | 4번. 사용자 관점 비교표와 증거, 쉽게 모방되는 부분까지 점검 |
| Q3-2 수익 구조 | 6번에 일부 사용. 공공적 효과·운영 지속 가능성이 중심이며 매출은 검증할 가설로만 제시 |

## 2. 10페이지 배분안

**별도 표지·목차 없이 공식 제목과 팀 정보부터 시작한다. 그림·표·참고자료까지 합쳐 10페이지 이내다.**

| 페이지 | 공식 항목 | 담을 내용 |
|---|---|---|
| 1 | 1. 제안 배경 및 출품작 소개 | 팀·서비스명, 문제, 대상, 한 줄 소개, 이용 흐름 |
| 2~3 | 2. AI학습·분석 도구 활용 및 AI 기술 적용 세부 내용 | 도착 시점 예측, 학습·검증 방법, 비교 실험, 한계 |
| 4~5 | 3. 출품작 핵심내용 | 공공데이터 필수 표, 데이터 결합, 출입·요금·추천 구조 |
| 6 | 4. 기존 서비스와의 독창성 | 증거 있는 비교표, 사용자 차별점, 모방 가능한 부분 |
| 7~8 | 5. 출품작의 완성도 | 실제 화면·시나리오, 구현/연결/실증 상태, 안전한 예외 처리 |
| 9~10 상단 | 6. 출품작의 발전 가능성 | 시민·행정 효과, 운영 비용, 검증 및 확장 로드맵 |
| 10 하단 | 7. 기타 참고 자료 | 주요 근거 색인, 데모·저장소 링크, 한계·재현 자료 |

글자 수보다 최종 배치가 우선이다. AI 원리와 데이터 설명을 중복하지 않는다. 2번은 ‘어떻게 예측했고 검증했나’, 3번은 ‘데이터를 어떻게 실제 서비스에 연결했나’로 구분한다.

```text
너는 「2026년 안양시 공공데이터·AI 활용 대학생 경진대회」의 제품 및 서비스 개발 사업계획서를 함께 작성하는 편집자다.
창업지원금 신청서가 아니라 시민의 문제 해결, 공공데이터 활용, AI 적용, 완성도, 발전 가능성을 설명하는 계획서다.

[팀명: 야도란]
[서비스명: 파킹안양 — 안양 공영주차장 도착 시점 혼잡 예측·요금 비교 추천 서비스]
[대상: 안양 역세권·상권·공공시설 방문 운전자 중 주차 탐색과 비용 비교가 필요한 사람]
[핵심 가치: 지금 비어 있는 곳이 아니라 도착했을 때 이용할 가능성이 높은 곳을, 주차시간에 맞는 요금과 함께 비교]
[범위: 안양 공영주차장 89곳을 대상으로 데이터 수집·진단. 모든 곳에서 예측이나 추천이 가능하다는 뜻은 아님]
[현재 서비스 데이터: parking.db가 주 데이터. gits.db는 예비·대조·추가 실험용 (.db파일로 얘기하지말고 어느 사이트에서 가져왔는지)]
[주요 기능: 목적지·주차시간 입력, 도보순/요금순 추천, 도착 시점 혼잡확률 기반 강등, 확인된 입출차 제한 반영, 유료시간·누진요금·일일권 비교]

먼저 실제 파일을 읽어라:
- 공용-프로젝트-컨텍스트.md: 배경과 연구 이력. 최신 구현 상태는 별도 파일과 대조
- dev_todo.md, src/serve/, tests/: 현재 구현과 남은 개발
- docs/reports/tables/a22b_three_line.csv, a22b_manifest.json: 최신 7일 점유 예측 평가
- reports/tables/a25_cutoff_summary.csv, a25_manifest.json: A/B/C 혼잡 강등 평가
- data/processed/prediction_accuracy.csv: 현재 서비스 노출 게이트
- reports/u11_report.md, reports/u11_status.json: 예측구간·확률보정의 이전 한계 확인
- reports/태영.txt 및 실제 조사 CSV: 확인된 출입·과금 정보
파일이 없거나 읽을 수 없으면 읽었다고 하지 말고 [확인 필요]로 표시하라.

작성 규칙:
1. ‘구현됨 / 실제 데이터 연결됨 / 테스트됨 / 현장 실증됨 / 계획’을 분리한다. 함수 구현만으로 서비스 완성이라 쓰지 않는다.
2. 최신 사실과 옛 실험 결과가 다르면 날짜·조건을 밝히고 최신 근거를 우선한다. 문서 간 충돌도 표시한다.
3. 조사·사용자 인터뷰·절감 효과·매출·파트너십·스크린샷을 만들지 않는다. 수치마다 파일/표 또는 공식 출처를 붙인다.
4. full_prob의 평가 사건은 점유율 90% 이상인 ‘혼잡’이다. 실제 빈자리 0개나 주차 실패 확률로 바꿔 쓰지 않는다.
5. AI 강등 없음과 있음의 차이만 제시하지 않는다. 현재 점유율만으로 강등하는 기준과도 비교하여 AI의 추가 기여를 설명한다.
6. U11은 예측구간 평가가 partial이었던 이전 결과다. 이후 p50 정확도 평가와 서비스 노출 게이트가 추가됐지만, 이를 U11 예측구간 전체 통과로 바꿔 쓰지 않는다.
7. p10~p90 예측구간은 검증 미완료로 비노출이다. 서비스 노출 게이트 181/548은 같은 7일 자료의 전·후반 검사이므로 독립 기간 인증이나 외부 인증으로 표현하지 않는다.
8. 조사 데이터·예측 가능시간 규칙이 실제 적재됐는지 확인한다. 차단 엔진 구현과 실제 예측 활성화는 별개다.
9. 경쟁사의 기능 부재는 확인일·공식 문서·실제 화면 근거 없이 단정하지 않는다. ‘우리가 무조건 이긴다’, ‘국내 최초’ 등은 쓰지 않는다.
10. 공공데이터의 제공기관·정확한 데이터명·공식 상세 URL·실제 사용 위치를 확인한다. 내부 API를 공공데이터포털 등록 데이터로 둔갑시키지 않는다.
11. 쉬운 한국어로 쓴다. 외국어 혼입, 중복 어미, 근거 없는 최상급 표현을 검사한다.

내가 지정한 항목만 작성하라. 결과는 ① 제출용 초안 ② 넣을 표/그림 ③ 확인·수정할 대괄호 목록으로 나눠라.
확인 메모와 미확인 입력값을 최종 제출 본문에 그대로 넣지 않는다.
```

## 4. 공식 항목별 프롬프트

### 1번 — 제안 배경 및 출품작 소개 / 1페이지

```text
공통 작성 규칙을 적용하여 공식 양식 1번을 작성해줘.

[문제 장면: 석수역 근처에 차를 세우려는 운전자가 가까운 주차장을 골랐지만 이동하는 동안 혼잡해질 수 있다. 유료시간과 무료시간을 걸쳐 주차할 때 최종 비용도 한눈에 비교하기 어렵다. 설명용 가상 장면이며 실제 피해 사례는 아님]
[대상 고객: 안양 역세권·상권 방문자, 공영주차장 이용 운전자]
[기존 불편: 현재 정보와 도착 시점의 차이, 주차시간별 요금 비교 부담, 요금징수시간과 실제 출입시간의 혼동]
[해결: 목적지와 주차시간을 입력하면 도착 시점 혼잡도, 예상 요금, 목적지까지 도보시간을 함께 비교]
[이용 경로: 목적지 입력 → 주차시간 입력 → 후보 조회 → 도착·예상 출차 확인 → 이용 불가 제외 → 혼잡·요금 계산 → 도보순/요금순 비교 → 길찾기]
[공익 목적: 주차 탐색 부담과 불필요한 이동을 줄이는 시민 대면 서비스. 단속 효율화 서비스가 아님]
[실제 인터뷰·경험 근거: 아직 정리되지 않음. 확보한 자료만 추후 추가]

먼저 과장 없는 한 줄 소개를 3개 제안하고, 가장 쉬운 문장으로 시작해줘.
‘누가 불편한가 → 무엇이 부족한가 → 우리 서비스가 어떤 선택을 돕는가’ 순서로 구성해줘.
약 800~1,100자와 짧은 이용 흐름 하나를 기준으로 1페이지에 맞춰줘.
검증하지 않은 주차 탐색 시간·탄소 절감 수치를 넣지 말고, 예상 효과와 확인된 효과를 구분해줘.
```

### 2번 — AI학습·분석 도구 활용 및 AI 기술 적용 세부 내용 / 2페이지

```text
공통 작성 규칙을 적용하여 공식 양식 2번을 작성해줘.

[AI가 필요한 이유: 현재 점유율이 아니라 차량이 도착할 미래 시점의 혼잡을 판단하기 위해]
[예측 시간: 15·30·60·120분. 실제 API의 시간 선택·보간 방식은 코드 확인 후 서술]
[예측 대상: 도착 시점 점유율 및 점유율90% 이상 혼잡확률]
[모델: 현재값 대비 변화량 타깃과 분위 예측, 확률 보정. 정확한 알고리즘·라이브러리·피처는 학습 코드와 모델 산출물 확인]
[서비스 적용: full_prob>0.5인 후보를 도보순·요금순 목록 뒤로 강등. 화면의 확률 표현은 검증 상태와 구분]
[평가 방법: 시간 순서가 섞이지 않는 rolling-origin, 학습·보정·평가 분리, 미래 타깃 누출 방지]
[비교 기준: A 강등 없음 / B AI 혼잡확률 강등 / C 현재 점유율90% 이상 강등]
[A25 결과: 15·30·60·120분, 각 축 유효 질의2875건. 요금순 A의 도착시 고혼잡1위557건→B36건, C가 걸러낸493건 대비 B가 추가28건 감소. 도보순 A607건→B38건, C가 걸러낸541건 대비 B가 추가28건 감소. 전체 순위 변경은 요금순28.0%·도보순29.8%, top1 변경은19.7%·22.6%]
[한계: 2875개가 독립 사용자2875명이 아니며 실제 주차 실패가 아니라 도착 시 점유율90% 이상 사건이다. cutoff0.5는 같은 홀드아웃을 참고해 선택했으므로 새 기간 재검증이 필요하다]
[미완료: 예측 구간 커버리지 partial, 확률 보정 일부 미통과, 현장 사용자 실증 미확인]
[분석 도구: 실제 Python 패키지·DB·실험 스크립트를 확인해서 입력. 개발용 생성형 AI와 서비스 예측 모델을 혼동하지 않음]

1페이지는 입력 데이터·모델·예측 출력·추천 반영을, 다음 페이지는 평가 설계·A/B/C 결과·한계를 설명해줘.
‘AI를 빼도 순위가 같다면 왜 필요한가?’에 답하되 p50 순위 변화와 혼잡확률 강등 효과를 구분해줘.
‘헛걸음을97% 방지했다’는 표현 대신 해당 실험에서 혼잡 기준 추천을 얼마나 줄였는지 써줘.
결과표의 분모·기간·사건 정의를 표 아래에 표시해줘. 수치는 파일에서 다시 계산·대조해줘.
```

### 3번 — 출품작 핵심내용 / 2페이지

```text
공통 작성 규칙을 적용하여 공식 양식 3번을 작성해줘.

[주요 데이터 후보: 안양도시공사 주차시설 기본정보, 안양 주차포털 실시간 점유정보, 실제 활용이 확인되는 주차장 공공데이터, 안양시 주차장 요금 조례]
```
